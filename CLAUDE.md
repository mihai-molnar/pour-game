# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A side-view incremental pouring game in Godot 4.5 (Forward Plus), hosted at https://github.com/mihai-molnar/pour-game (branch `master`; the local folder is `pour-prototype/`). Pourer on the right, glass on the left: hold DOWN to tilt and pour, release and the pourer swings back upright while liquid already in the air (plus a little from the lip) keeps landing. The goal is to fill the glass to a fill line drawn on it — close to the line pays coins, exact pays the most, overflowing pays nothing.

**Current state: slice 2 (second drink + mixed rounds) is implemented, playtested and merged** (2026-10-15; user verdict "looks good") — spec `docs/superpowers/specs/2026-10-15-second-drink-design.md`, plan in `docs/superpowers/plans/`. It builds on slice 1 (the round loop, playtested and merged 2026-10-15, spec `docs/superpowers/specs/2026-10-15-round-loop-design.md`): a round is 30 s, serve as many glasses as you can, each scored PERFECT/GOOD/MISS/SPILL, with a streak multiplier (x1 to x3), a "LAST CALL!" phase when the timer hits 0:00 (liquid in the air still lands and the last glass is auto-served), then a summary screen and the next round; coins carry across rounds. Slice 2 adds wine (`drinks/wine.tres`): a bottle held tipped at 55° over a big stemmed glass, line at the bowl's widest point, paying 15 / 12–3. Round 1 is all water; round 2 unlocks wine ("NEW DRINK: WINE") and opens with it, then each glass is a random owned drink (seeded `GameState.rng`). A served glass vanishes with a puff and the next slides in from the left; a drink change brings the other pourer, full, from the right. The pitcher refills in place; an empty bottle is replaced by a new corked one that is uncorked. No shop yet.

**Scoring steps** (playtested and merged 2026-10-15; asked for in the slice 2 playtest): a glass is scored by how many pixel rows its settled surface sits from the line, as drawn — PERFECT 0–1 rows, GOOD 2–3, GOOD ENOUGH 4–6 (holds the streak), MISS beyond, SPILL if it overflowed. Each step pays a fixed amount per drink (water 10 / 6 / 3, wine 15 / 9 / 5), multiplied by the streak multiplier; a spill costs `spill_coins` (water 6, wine 9), unmultiplied, and the coin total never goes below 0. The streak counts GOOD-or-better glasses in a row (resets each round): x1 for the first glass, x1.2 after the second, then +0.1 per glass up to x3 (`streak_start` 2, `streak_step` 0.1, `streak_max` 3.0 in `GameState.stats`, for shop upgrades). The multiplier sits right after the coin counter; a grown value pops up big in the upper middle of the screen and flies into place, a reset does a "denied" shake and turns into x1.

**Smooth art style** (implemented and merged 2026-10-18 at the user's request; spec `docs/superpowers/specs/2026-10-18-smooth-art-style-design.md`, browser mockup beside it, plan in `docs/superpowers/plans/`): the pixel-art look ("looks like it was made in MS Paint") is replaced by a smooth, stylized one. Rendering is `canvas_items` at window resolution with 2D MSAA and a static camera 1.75× closer; an evening bar (backlit shelves of bottles, mirror, pendant lamps, neon cocktail sign, polished counter) behind; glassware with thick gradient walls, streaks, rim light and contact shadows; see-through liquid that refracts and tints the bar behind it; a Fredoka HUD in soft pills. Gameplay is untouched (the `--sweep` tables are byte-identical to before).

**Next slices:** the between-rounds upgrade shop (slice 3; the `GameState.stats` seam is in place, and `GameState.ROUND_UNLOCKS` is the stand-in it replaces). Open question from the slice 2 spec: let the player choose the round's drink mix in the shop, so late rounds aren't stuck serving cheap water.

**Known deferred work:**
- Playtest-confirmed as fine for now (revisit only if it comes up again): auto-refill triggers only below 1 % of full, so a near-empty pourer must be tipped far before it refills; Space is ignored while refilling.
- A drink change always brings a full pourer, so the bottle's replace-and-uncork refill only shows after three or more wine glasses in a row.

## Commands

```bash
GODOT="/Users/mihai/Godot games/Godot.app/Contents/MacOS/Godot"   # Godot 4.5.1; quote it — the path has a space

"$GODOT" --path .                                   # play
"$GODOT" --headless --path . --import               # import assets / rebuild the class_name cache
"$GODOT" --headless --path . -- --sweep             # tuning table (or --sweep=wine): hold length -> fill %, overshoot after release, settle time, spill
"$GODOT" --headless --path . --quit-after 900 --script res://tools/run_check.gd -- --check=all   # all checks (or --check=<name>)
"$GODOT" --path . --windowed --resolution 1280x720 -- --autoplay --seed=11 --shots=/abs/prefix --shot-every=1.5 --quit=70   # autoplayed rounds + screenshots at the window's resolution (round 2, with wine, starts ~33 s in)
tools/make_background.sh                            # regenerate art/background.png from tools/background/bar.html (needs Google Chrome), then --import
```

- Checks: `tools/checks/check_{drinks,scoring,glass,pourer,ui,round,bubbles,arrival,view,vessel_art,stream}.gd`, each `extends CheckBase` (`tools/checks/check_base.gd`) and implementing `run()` with `expect`/`eq`/`near`. Success = one `check_<name>: OK` line per check (bubbles also prints `outside the glass: 0`). A crashed runner still exits 0 under `--quit-after`, so judge by the OK lines, not the exit code. Always keep `--quit-after N` (macOS has no `timeout`; a script error can leave headless Godot running forever).
- Why the runner exists: a `--script` file is compiled before autoloads exist, so it can't reference `GameState` or any class that uses it (verified on 4.5.1). `tools/run_check.gd` therefore loads each check at runtime after autoloads, calls `GameState.reset_session(1)` before each check, and fails a check on any logged script error (Godot 4.5 `Logger`), not only on failed expectations.
- Dev flags (parsed in `main.gd`): `--sweep[=drink_id]` (loads `res://drinks/<id>.tres`, default water), `--autoplay` (the `Autopilot` plays rounds), `--seed=N` (seeds the drink picks so a run repeats), `--shots=PREFIX` (PNGs of the game area at the window's physical resolution every `--shot-every=S` seconds), `--quit=S`. The project opens maximized (`window/size/mode=2`), which ignores `--resolution`: to test another window size, put a temporary `override.cfg` in the project root (`[display]` with `window/size/mode=0` and `window/size/window_width_override` / `_height_override`) and delete it afterwards. A 4:3 window letterboxes (a 1024×768 window shoots 1024×576).
- Headless runs use a dummy renderer: shaders are not compiled there, so shader changes are verified with a windowed `--shots` run (grep its output for `SHADER ERROR`).
- "Could not find type"/"Identifier not declared" for class_names that exist means a stale `.godot` class cache (scripts added outside the editor): run `--import` first.
- Live tuning: run from the editor (F5), switch the Scene dock to **Remote**, select `Pourer`/`Glass`/`Stream` and edit the exported values; the per-vessel liquid look (lens, wobble, edge glow) is on each vessel's `Liquid` node `ShaderMaterial`, the per-drink look (`liquid_color`, `liquid_absorb`, `liquid_scatter`) in the `DrinkDef`. Gameplay tunables (round length, tolerances, multipliers) live in `GameState.stats`.

## Architecture

**Rendering.** The world is still 640×360 game pixels ("world px": every coordinate, speed, size and volume; the counter top is y=280), but it is drawn smooth at the window's resolution: `stretch/mode="canvas_items"` (aspect `keep`, fractional scaling, base 640×360 so the HUD is laid out in 640×360 units too), linear filtering, 2D MSAA 4×, no pixel snapping. A static `Camera2D` (`Main.CAMERA_CENTER` (300, 186), `CAMERA_ZOOM` 1.75 — the `Camera` node in `main.tscn` must match, `check_view` asserts it; `Main.view_rect()` is the world rect it shows, about x 117–483, y 83–289; at that zoom a pitcher's first two glasses stay clear of the HUD pills, its third may pass behind the timer) frames the glass and pourer; `Main.world_to_hud(p)` maps a world point into HUD coordinates (popups). One world px is 3.5 screen px at 1280×720, so a scoring row is visible: what is drawn must sit exactly where the sim says. The vessels are drawn procedurally in `_draw` from rounded copies of the `DrinkDef` polygons (`VesselArt.rounded`); the physics keeps the sharp originals, so keep shapes in the `DrinkDef` and only round at draw time.

**Units.** Liquid volume is area in px², shared by pourer and glass. Gameplay truth is these numbers; waves, splashes, bubbles and the stream's look are visual only.

**Data and state.**
- `drink_def.gd` (`DrinkDef`) + `drinks/*.tres` — drinks are data (colors, fill-line fraction, vessel shapes, payout, pour feel, look). The shapes drive both drawing and physics; pourer shapes are authored upright. `pourer_rest_deg` is the angle a pourer is held at (bottle 55°); `pourer_glass_color` tints its glass (alpha = body tint, walls 3× capped at 0.85; tinted glass also shades the liquid); `refill_style` is `IN_PLACE` (pitcher) or `NEW_BOTTLE`. Look: `liquid_absorb` (per-px absorption, rgb: water lets the bar through, wine swallows it), `liquid_scatter` (colour the liquid gives off itself), `glass_corner_radius` / `pourer_corner_radius` (draw-time rounding), `pourer_label` / `pourer_foil` (rects on the bottle, zero = none).
- `game_state.gd` (autoload `GameState`) — coins, round number, owned drinks (start `[WATER]`; `ROUND_UNLOCKS = {2: wine}` via `unlock_for_round(n)`), `rng` (seeded drink picks), `reset_session(seed)`, and `stats`, the upgrade seam: `round_duration` 30, `perfect_rows` 1, `good_rows` 3, `ok_rows` 6 (scoring step limits in pixel rows), `streak_start` 2, `streak_step` 0.1, `streak_max` 3.0 (the streak multiplier), `coin_mult` 1.0, `pour_speed_mult` 1.0, `refill_time` 1.0. Gameplay reads these at point of use; never hard-code a value that has a stats key.
- `scoring.gd` (`Scoring`) — pure rules: step from rows off the line (`band(rows, spilled, stats)`), fixed coins per step from the `DrinkDef` (`perfect_coins` / `good_coins` / `ok_coins`; a spill is `-spill_coins`), the streak (`next_streak`: GOOD-or-better glasses in a row; GOOD ENOUGH holds, MISS/SPILL/new round reset) and `multiplier(streak, stats)` (x1 until `streak_start`, then 1 + `streak_step` × streak, capped at `streak_max`). Earnings use the multiplier *before* the glass and `coin_mult`; a spill's cost uses neither. `Main` floors the coin total at 0 (`r.coins` is what was actually won or lost).

**Simulation loop.** `Main` is a phase machine (INTRO, PLAYING, LAST_CALL, SUMMARY). `main.tick(dt, hold)` is the only place round logic advances (tweens are HUD visuals only); each tick runs the fixed 60 Hz sim in a fixed order: `pourer.step()` returns the volume that left the spout -> `stream.emit(spout, exit_velocity, vol, dt)` -> `stream.step(dt, glass)` -> `glass.step(dt)`. The sweep, the checks and `Autopilot` call `tick()` in tight loops, so gameplay must stay deterministic (randomness only for visuals: bubbles, drips, droplets). `manual` mode stops `_physics_process` from ticking so checks and tools drive `tick()` themselves. Serving: Space queues a serve that fires once `!pourer.is_pouring()` and `stream.is_empty()` (in-flight liquid always counts); serves under 1 % of capacity are ignored; Space is ignored while a glass or pourer arrives (`is_swapping()`) or while the pourer `is_busy()` (arriving, corked or refilling). After a serve the glass vanishes with a puff and the next glass (`_pick_drink()`: a just-unlocked drink first, else a uniform pick from `owned_drinks` via `GameState.rng`) arrives in 0.3 s; if its drink differs, the pourer vanishes too and the new one arrives full. Each round's first glass and pourer arrive during INTRO. LAST_CALL auto-serves after 3 s idle (DOWN not held, not pouring, pourer not busy, nothing in the air); the last glass vanishes and the summary follows 0.35 s later; there is no separate landing trigger. Holding DOWN across the round end into the next INTRO does nothing (INTRO ignores input).

- `pourer.gd` (renamed from `pitcher.gd`) — node origin = spout lip = rotation pivot; `rotation = -(rest + tilt)` where rest = `pourer_rest_deg` (tilt, `max_tilt_deg` and "upright" all count from the rest angle). Holding approaches `tilt_speed_deg` until liquid reaches the lip, then the slower `pour_tilt_speed_deg` (careful hands); releasing applies a constant `return_force` plus damping (momentum carries it a little further, then it eases back; small bounce at rest). Pouring is geometric: `excess = volume − area(interior ∩ half-plane below the line through the lip at local angle tilt + slosh)`; that excess drains at `pour_rate` (`pour_speed_mult` only scales the tilt speeds `tilt_speed_deg` and `pour_tilt_speed_deg`, not `pour_rate`) with exit speed growing with √excess. Slosh angle is driven by tilt acceleration. Auto-refill: below 1 % of full volume the pourer swings upright ignoring DOWN, then over `refill_time` either fills in place (`IN_PLACE`) or vanishes (`vanished` signal), a new corked bottle arrives (0.3 s) and wiggles until the cork pops (`popped`) at `max(refill_time − 0.3, 0.1)` (`NEW_BOTTLE`); liquid already in the air still lands. `arrive(d, at)` slides it in from x = 680 (a bottle arrives corked and pops `POP_TIME` 0.15 s after landing); `place(at)` puts it home at once; `reset()` also returns it home. The arrival lean turns only its `Back`/`Liquid`/`Front` layers. Drawing: `drawn_liquid_polygons()` (the liquid cut to the rounded interior, slivers dropped), the glass body in `Back`, walls in a gradient built from `pourer_glass_color`, the surface sheen, label and foil from the `DrinkDef`, a lip ring on a bottle / a rim line on a pitcher, the handle as a thick glassy polyline, the cork while `corked`; `draw_reflection(ci)` for the counter.
- `stream.gd` — one ballistic `Parcel` per pouring tick. Crossing the rim decides inside (clamped to the opening, lands on `glass.surface_y_world_at` -> `glass.receive`) vs missed (falls to `table_y`, counted as spilled). Below `drip_flow` volume accumulates into discrete drops. Drawing: each run of parcels emitted on consecutive ticks (plus the landing point while landing and the spout while flow is continuous) is one smooth ribbon (`Stream.ribbon(points, widths)`), its width set at the spout from the flow and thinning as the parcel speeds up (`width · sqrt(speed0 / speed)`), with a thin bright core; drops and splash droplets are small discs.
- `glass.gd` — the interior polygon is rasterized once into per-column spans and per-row areas (world px), so `level_for(volume)` is exact and capacity = interior pixel count. The surface is a 1D wave equation per column, excited by impacts and by the glass's horizontal acceleration. Bubbles must stay within the column spans (`_inside`) and pop at the surface or at their column's top (a bowl narrowing toward the rim). An empty glass doesn't slosh from its own motion. The target is fixed per drink (`fill_fraction × capacity`), not random; `reset()` only empties the glass. `rows_from_line(vol)` = rows between the settled surface and the line (what scoring uses; it rounds both to whole rows). Drawing: `liquid_polygon()` = the calm level minus each column's wave, down to the floor, cut to the rounded interior (a calm glass's drawn top is exactly `level_for(volume)`; `check_glass` pins it). `line_y()` = `round(target_y)`, where the fill line is drawn; `band_edges(n)` = `line_y() ± (n + 0.5)` cut to the glass — the rows scoring treats as within n of the line; the line's dark band spans PERFECT (±`perfect_rows`), the bracket (`bracket_x()`, 3 px left of the outer wall across the band) spans GOOD ENOUGH (±`ok_rows`) with inner ticks at ±`good_rows`. Three layers: `Back` (frost body, soft outline), `Liquid` (shader), `Front` (gradient walls, surface sheen, bubbles tinted by the drink, streaks, rim light, rim, drips, band, fill line). `draw_reflection(ci)` draws it for the counter reflection. `arrive(d, at)` sets it up empty at x = −40 and slides it in (`landed` signal); `place(at)`, `vanish()`. The lean turns only its layers, never the node, so landing liquid and the rim/opening helpers never see it.
- `arrival.gd` (`Arrival`) — pure slide/lean curves of the time since an arrival started (0.3 s, ≤ 3 px overshoot, 6° lean, wobble ≤ 0.15 s after) and `pivot()`, the lowest leading corner a vessel tips over. Vessels step them inside `tick()`, so arrivals stay deterministic.
- `effects.gd` (`Effects`) — visual-only soft bits (`Kind`: PUFF blobs where something vanishes, DOT specks for dust and cork spray, the tumbling CORK), stepped from `tick()`, capped at 120.
- `liquid.gdshader` — on each vessel's `Liquid` `DrawLayer`. Samples `hint_screen_texture` (linear) with a lens + wobble shift along the vessel's local x axis, turned into a screen-UV offset through `dFdx`/`dFdy` of the local position and `SCREEN_UV` (so it holds at any window size, zoom or tilt); tints it by Beer–Lambert absorption over the view path (`2·half_width·sqrt(1−rel²)`, a little deeper toward the bottom) and adds `tint · scatter`; a faint edge glow near the walls. Vessel scripts set `tint`/`absorb`/`scatter` from the `DrinkDef` and the geometry uniforms (`center_x`, `half_width`, `surface_y`); the per-vessel look uniforms (`lens_strength`, `wobble_px`, `edge_glow`) live in the materials in `main.tscn`. Godot copies the screen texture once, at the first item that reads it, so liquids only refract what was drawn before the glass's liquid (background, reflection, shadows, the glass's `Back`).
- `draw_layer.gd` — forwards `_draw` to a callable, so a vessel draws its `Back`, shaded `Liquid` and `Front` layers separately. `vessel_art.gd` (`VesselArt`) — static smooth-drawing helpers: `rounded(poly, r, keep_top)`, `walls(outer, interior)` (the wall area with the top open; plain `clip_polygons` returns the inside as a hole), `gradient`/`draw_hgradient` (horizontal gradient fills via UVs), `clear_glass_walls()`, `span_at`, `inner_streak`/`draw_streak`, `draw_rim_light`, `draw_soft_ellipse` (a cached radial texture). `shadows.gd` (`Shadows`) — soft contact shadows under the glass and the pourer (fading as it lifts), in world space. `reflection.gd` (`Reflection`) — a faint mirror image of both vessels in the counter top: it draws the strip as a mask (`clip_children` = CLIP_CHILDREN_ONLY) and its `Mirror` child (modulate alpha 0.16) calls the vessels' `draw_reflection`. Scene order: Background, Camera, Reflection, Shadows, Glass (Back, Liquid, Front), Stream, Pourer (Back, Liquid, Front), Effects, Hud, RoundSummary — the stream draws before the pourer so it appears from behind the spout.
- `hud.gd` (`Hud`) — built in code and laid out by hand in 640×360 units (no containers, so positions are known at once): Fredoka via `Hud.font(weight)` (a cached `FontVariation`; 600 by default), soft dark pills (`Hud.pill_style()`). Coins top left as a drawn coin icon + number, the streak multiplier after a thin divider in the same pill (dim at x1, gold above; a grown value pops up at 3× in the upper middle — `streak_flyer` — and flies into place, a reset does a decaying "denied" shake and turns into x1 — `set_streak(mult, animate)`), timer top center (red in the last 5 s), result popups at the glass (coins only, coloured by step: gold PERFECT, green GOOD, frost GOOD ENOUGH, red `0` MISS, red `-N` spill; they pop in, float and fade), ROUND/LAST CALL banners (`round_banner()` adds "NEW DRINK: <NAME>" on an unlock round), the key hint (or "SERVING..."/"REFILLING...") in a pill bottom right, F1 debug readout. Purely visual.
- `round_summary.gd/.tscn` (`RoundSummary`) — end-of-round overlay: a rounded dark panel with GLASSES, PERFECT, BEST STREAK (the best multiplier reached), COINS (signed: a round of spills can be negative), TOTAL as two aligned columns (`body_text()` joins them per row), and a gold NEXT ROUND (SPACE) button. Space and the button are ignored for the first `input_lock` (0.5 s) after it appears, so a stray press from the last serve can't skip the results.
- `autopilot.gd` (`Autopilot`) — scripted player used by `--autoplay` and the round check; returns the hold state per tick and requests serves; `release_at` is per drink id (water 0.94, wine 0.86 — both land within ~2 rows).
- `main.gd` — input (physical DOWN/Space/F1/Esc), builds the HUD, owns the camera constants, the phase machine, the drink picks, the arrivals on serve/round start and the dev flags; hands `glass`/`pourer` to `Shadows` and `Reflection`. `results` entries carry `drink` (the id). `BACKGROUND_RECT` = the world rect `art/background.png` covers (Rect2(110, 76, 380, 220) at 7 image px per world px).

**Current tuning baseline** (from `--sweep`, water, full pourer, `pour_tilt_speed_deg = 11.5`): pouring starts with a 0.6 s hold; the hold nearest the fill line is 3.0 s (−1.0 %); 12.4–12.7 % of glass capacity lands after release for fills of 72–89 % (the overshoot the player learns to anticipate); a full pourer is 2.47 glasses at the 90 % line. Half-full pourer: pouring starts ~1.4 s, nearest-line hold 2.6 s. Scoring counts pixel rows: PERFECT (±1 row as drawn) is about ±2.7 % of the target on this glass, GOOD ENOUGH's ±6 rows about ±11 %.

Wine (`--sweep=wine`, full bottle, `pour_tilt_speed_deg = 5`, `max_flow = 1000`, `stream_speed_k = 3`): pouring starts with a 0.6 s hold; nearest-line hold 2.0 s (−3.7 %); 15–17 % of glass capacity (about 29 % of the target) lands after release; fill moves 12 %/0.2 s near the line (water ~10); no spill up to the GOOD band; a full bottle is 2.67 glasses. Half-full: pouring starts ~1.0 s, line between 2.2 and 2.4 s. The wine glass was sized (before scoring moved to rows) so a ±3 % PERFECT was ±1 row; with rows, its bands are as wide in pixels as water's.

## Visual identity

- Smooth and stylized (see the spec and its browser mockup): a dim, warm evening bar behind; glass and pourers large and central, reading as glass (thick walls with a light gradient, streaks, rim light, contact shadows); see-through liquid; soft dark pills for the HUD.
- Background: `tools/background/bar.html` draws it on a canvas in world units (far layers blurred ~2.5 image px, the bottles ~1.6, the counter sharp; the area behind the play space darkened a little so the vessels read); `tools/make_background.sh` renders it to `art/background.png` (2660×1540, mipmapped) through headless Chrome. Behind the vessels keep mid-level detail so the refraction has something to bend, but nothing brighter than the vessels' highlights.
- Colors: named colours live in `palette.gd` (`class_name Palette`, started from ENDESGA 32, now with additions like `LABEL`); reference `Palette.*` rather than literals in game code. Gradients and alpha variants between them are fine. The bar's colours live in `bar.html` only (the game never reads them).
- Fill line and band: a thin white line on the target's row over a dark band spanning the PERFECT rows, plus a bracket left of the glass spanning GOOD ENOUGH with inner ticks where GOOD ends, all dark-underlaid so they read on the bar. Popup text has a dark outline.
- Font: Fredoka (`fonts/Fredoka.ttf`, variable weight 300–700, SIL OFL — licence beside it), SemiBold 600 for the HUD, Bold 700 for popups, banners and the summary title.

## Gotchas

- GDScript `const` can't hold `PackedVector2Array(...)` (not a constant expression) — vessel shapes are member `var`s.
- `FontVariation.variation_opentype` needs the integer tag (`TextServerManager.get_primary_interface().name_to_tag("wght")`); a `"wght"` string key is silently ignored (the font renders at its default weight, 300 for Fredoka).
- `CanvasItem.clip_children`: 1 = CLIP_CHILDREN_ONLY (mask only), 2 = CLIP_CHILDREN_AND_DRAW (the mask is drawn too).
- `draw_colored_polygon` logs "triangulation failed" for slivers and folded outlines — drop polygons under 0.5 px² and check `Geometry2D.triangulate_polygon` before drawing generated outlines. Headless runs never show that error (the dummy renderer skips triangulation), so checks must call `Geometry2D.triangulate_polygon` themselves.
- `Geometry2D.clip_polyline_with_polygon` returns the part *outside* the polygon; use `intersect_polyline_with_polygon` for the inside.
- `.godot/` is editor cache — never edit or commit it. Commit Godot's `.uid` sidecars; `main.tscn` will gain `uid=` attributes on first editor save — commit that rewrite too.
